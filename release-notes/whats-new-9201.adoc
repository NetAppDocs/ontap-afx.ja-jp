[role="lead"]
AFXストレージシステムで利用可能なONTAP 9.20.1に含まれる新機能について説明します。


NOTE: AFXには、ONTAP 9.20.1で利用可能な新機能がいくつかあります。これらのうちいくつかはAFX固有のものですが、その他多くは共通の製品基盤から派生したものです。下記に説明するAFXの機能を確認することに加えて、以下も参照してください https://docs.netapp.com/us-en/ontap/release-notes/whats-new-9201.html["ONTAP 9.20.1の新機能"^]。



[[data-protection]]
== データ保護

[cols="30%,70%"]
|===
| 更新 | 説明 


 a| 
非SnapLockソース整合性グループからSnapLock for SnapVault宛先整合性グループへのレプリケーション
 a| 
非SnapLockのソース整合性グループから、SnapLock for SnapVaultのデスティネーション整合性グループにレプリケートできます。SnapLock for SnapVaultは、レプリケートされた整合性グループを誤った削除や悪意のある削除から保護します。



 a| 
NAS向けSnapMirrorアクティブ同期のオブジェクト制限
 a| 
SnapMirror active sync for NASにより、AFXプラットフォーム（4 x 4）でサポートされるボリューム数が600に増加します。



 a| 
SnapMirror同期災害復旧について学ぶ
 a| 
SnapMirror同期モードでは、AFXプラットフォームにおけるレプリケーション操作の数が600に増加します。



 a| 
強化されたSVMディザスタリカバリ
 a| 
ONTAP 9.20.1では、標準的な管理者権限によるボリューム変更ワークフローを使用して、SVM-DRデスティネーションボリューム上の選択されたボリューム変更属性を許可することで、SVMディザスタリカバリ機能が強化され、サポートによる支援が必要な手順が削減されます。このリリースでは、オプトインのSVM-DRクイック再同期サポートがFlexGroupコンスティチュエントにも拡張され、DRリハーサル、再同期、またはフリップ再同期ワークフローのあとに、FlexGroupを含む大規模なSVMがより迅速に保護状態に戻るのを支援します。



 a| 
元のソースボリュームへのSnapMirrorクラウドIn Placeリストア
 a| 
SnapMirrorクラウドはFlexVolボリュームのIn Placeリストア処理をサポートしており、クラウドスナップショットのリストア処理を元のソースボリュームに直接実行できます。ONTAPは最新の共通スナップショットを選択して増分転送を実行し、リストア時間を短縮します。

[[nas]]
== NAS

[cols="30%,70%"]
|===
| 更新 | 説明 


 a| 
Windows クライアントとの互換性とパフォーマンスを確保するため、NetApp ONTAP SMB プロトコルに NormaliseNameInfo のサポートを実装する
 a| 
Windowsクライアントは、単一のリクエストで正規のファイル名とディレクトリ名を取得できるため、ファイルを開く際の遅延が短縮され、企業向けデスクトップ、アプリケーション、ファイルサーバーにおけるSMB互換性が向上します。ONTAPは、開いているファイルとディレクトリの正規パスを自動的に返し、追加の設定なしに、Windows 11 24H2以降のクライアントでコンポーネントごとの検索を回避します。



 a| 
スペースの再利用を可能にするVAAI-NASによる自動UNMAPのサポート
 a| 
ONTAPは、NetApp NFS Plug-in for VMware VAAIを使用して、NFSデータストアの自動領域解放をサポートします。これにより、VMware ESXi 9.0以降のホストがUNMAP処理を発行した際に、シンプロビジョニングされたVMDKブロック範囲から領域を解放できます。



 a| 
ONTAP FlexVol ボリュームの最大ディレクトリサイズ
 a| 
ONTAPは、最大4GBのディレクトリサイズをサポートすることで、最大約2500万個のファイルを含む非常に大規模なディレクトリのパフォーマンスを向上させます。AIトレーニングなど、単一のディレクトリに非常に多くのファイルを生成するワークロードを実行しているお客様は、従来の大規模ディレクトリで見られたパフォーマンスの低下を回避できるというメリットが得られます。また、データ保護のフェイルオーバー後もディレクトリの完全なインデックスが維持されるため、レジリエンシが向上し、SnapMirror関係が解除された場合でもレプリケートされたコピーで高いパフォーマンスが発揮されます。この機能はAFXストレージシステムで利用可能であり、必要に応じて各ボリュームで有効にできます。



 a| 
SIDからUNIX IDへの自動変換をサポート
 a| 
ONTAPでは、LDAP接続されたSVM向けに、Windows SIDからPOSIX UID/GIDを生成および逆変換するための、SIDからUNIX IDへの自動変換サポートが導入されました。これにより、Active DirectoryでuidNumber/gidNumber属性を手動で管理する必要がなくなり、管理のオーバーヘッドが削減され、NFSとSMB全体で一貫したファイルアクセスを確保できるようになります。この業界標準に準拠した機能は、SSSDベースのNASプラットフォームから大規模ネットワークを移行し、IDマッピングの一貫性を維持したいお客様にとって特に価値があります。この機能はデフォルトでは無効になっており、SVMごとに設定します。

[[s3-object-storage]]
== S3オブジェクト ストレージ

[cols="30%,70%"]
|===
| 更新 | 説明 


| link:../administer/additional-ontap-svm.html["S3オブジェクトストレージ用のFPolicy"]  a| 
FPolicyは、S3オブジェクトワークフローのセキュリティ監視機能を提供します。これにより、ファイルおよびオブジェクトストレージ向けの統一されたFPolicyフレームワークが提供され、ハイブリッドデータ環境におけるセキュリティ運用が簡素化されます。S3オブジェクト向けのFPolicyは、オブジェクトの作成、削除、メタデータタグの変更を監視することで、セキュリティ、コンプライアンス、監査要件を満たすためのオブジェクトライフサイクル可視化機能を提供します。この機能は、パフォーマンスに影響を与えることなく、無停止での監視を提供します。



 a| 
柔軟なS3バケットサイズ設定
 a| 
ONTAPは、新しいS3バケットに対して設定可能なデフォルトサイズをサポートしています。これは、アプリケーションが容量を指定せずにS3 API経由でバケットを作成する際に、手動でのサイズ変更を減らすのに役立ちます。デフォルトサイズが設定されていない場合、バケット作成の動作は変更されません。



 a| 
ONTAP S3 NASバケットをFlexCache（FlexVolオリジン）で許可する
 a| 
ONTAP 9.20.1以降では、FlexCacheボリューム（オリジンがFlexVol）上のS3 NASバケットがサポートされます。単一オブジェクトに対するS3操作（PUT、GET、DELETE、HEAD、LIST）がサポートされています。基盤となるFlexVolボリュームがGranular Data Distributionをサポートしていないため、マルチパートアップロードはサポートされていません。



 a| 
FGオリジンを持つFCボリューム上のS3 NASバケットのCOPYオブジェクトをサポートします
 a| 
ONTAP 9.20.1以降、FlexCacheボリューム上のS3 NASバケットは、S3のCopyObjectおよびUploadPartCopy APIを使用したサーバ側のオブジェクト コピー処理をサポートします。同じFlexCache NASバケット内、またはFlexGroupボリュームをバックエンドとするS3 NASバケットからFlexCache NASバケットへ、オブジェクトをコピーできます。



 a| 
S3チェックサムの初期サポート
 a| 
ONTAP S3は、S3 NASバケット向けにAWS互換のCRC-64NVMEチェックサムをサポートしています。S3クライアントが、サポートされているアップロードおよびマルチパート操作のチェックサム情報を提供すると、ONTAPはチェックサムを検証して保存し、サポートされているGETおよびHEADリクエストに対してチェックサム情報を返します。

[[security]]
== セキュリティ

[cols="30%,70%"]
|===
| 更新 | 説明 


 a| 
ARP/AIスナップショット応答ポリシーの制御機能の強化
 a| 
ARP/AIが異常なアクティビティを検出した際にスナップショットを作成するかどうかを制御するために、SVMまたはボリュームレベルでARP/AIスナップショット応答ポリシーを設定できます。利用可能なポリシーは3つあります： `alert-with-proactive-and-periodic-snapshot`（デフォルト、既存の動作を維持）、 `alert-with-proactive-snapshot`（攻撃時のスナップショットのみ、定期的なスナップショットはなし）、および `alert-only`（アラートとイベントログのみ、スナップショットは作成されません）。9.20.1へのアップグレード後、ノードレベルのオプションが以前に変更されていない限り、デフォルトの定期スナップショットの最大カウントは6から2に変更され、デフォルトの保持期間は12時間から7時間に変更されます。詳細については、 https://docs.netapp.com/us-en/ontap/anti-ransomware/modify-snapshot-options-arpai.html["ARP/AIスナップショット応答ポリシーの制御機能の強化"^]を参照してください。



 a| 
データSVMのキー管理ワークフローの改善
 a| 
データSVMで外部キーマネージャを有効にすると、ONTAPは、そのSVMのボリューム暗号化キーを管理者スコープのキーマネージャから新しいデータSVMキーマネージャに自動的に移行できます。これにより、外部キー管理への移行が簡素化され、標準ワークフローにおける別途の手動移行手順が不要になります。



 a| 
MAV承認者としてのIdP、AD、LDAPグループのサポート
 a| 
MAV承認グループには、個々の管理者に加えて、IDプロバイダー（IdP）、Active Directory（AD）、およびLDAP（nsswitch）グループを承認者として含めることができます。サポートされているグループの種類には、Entra ID、ADFS、ADドメイングループ、およびLDAPグループが含まれます。IdP、AD、またはLDAPディレクトリでユーザーを追加または削除しても、MAV構成を変更する必要はありません。ユーザーのグループメンバーシップの変更は、ユーザーが次回ログインした際の再認証後に有効になります。security multi-admin-verify registered-operations showコマンドを使用すると、現在のクラスタで使用可能なMAV保護対象のすべての操作を表示できます。



 a| 
SNMPv3 SHA-512認証のサポート
 a| 
ONTAPは、SNMPv3ユーザー向けにSHA-512認証をサポートしています。この機能強化により、外部SNMPクライアントおよびスイッチ監視（SHA-512認証を必要とするスイッチを含む）において、より強力なSNMPv3認証を使用できるようになります。詳細については、ONTAPクラスタでのSNMPv3ユーザーの設定、およびイーサネットスイッチの健常性監視のためのSNMPv3の設定を参照してください。

詳細については、 https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["イーサネットスイッチの状態監視のためにSNMPv3を設定する"^]を参照してください。

[[storage-efficiency]]
== Storage Efficiency

[cols="30%,70%"]

| 更新 | 説明 


 a| 
自動重複排除スケジューラ（ADS）の最適化
 a| 
ONTAPはADS（自動重複排除スケジューラ）のパフォーマンスを向上させ、ノードあたりの同時重複排除セッション数を増やすとともに、よりスマートで的を絞ったスロットリングによってクライアントI/Oのバランスを最適化します。DPボリュームでの重複排除アクティビティ（SnapMirror転送によるもの）とグローバル重複排除セッションは、通常のボリューム重複排除と並行して管理されるため、競合とメタデータの増加が抑制されます。設定を変更することなく、特に混在ワークロード環境において、ストレージ効率化による削減効果を得ることができます。この機能はデフォルトで有効になっており、AFXストレージシステムで利用できます。

[[storage-resource-management]]
== ストレージ リソースの管理

[cols="30%,70%"]
|===
| 更新 | 説明 


 a| 
AFX 32ノードエンタープライズサポート
 a| 
ONTAP AFXクラスタを最大32ノードのフルスケールで展開し、エンタープライズ機能を完全にサポートすることで、従来は小規模なAFX環境でのみ利用可能だった機能と同等の機能を提供できます。これにより、エンタープライズのお客様、特にAI/MLのトレーニングやデータパイプラインを実行しているお客様は、階層化、データ保護、スナップショット、レジリエンシなどのエンタープライズ データ サービスを犠牲にすることなく、より大規模で高密度のストレージクラスタを構築できるようになります。NFS、SMB、S3、FlexGroup、FlexCacheを含むNASおよびオブジェクトプロトコルの完全なサポートが、HAおよびリカバリワークフローとともにこの規模で検証されており、AFXの導入規模が拡大しても信頼性の高い運用が保証されます。



 a| 
FabricPool の階層化
 a| 
FabricPoolは、データの活動状況に応じて、ハイパフォーマンスなローカル層と低コストのリモートクラウドまたは容量層の間でデータを移動するONTAPの機能です。FabricPoolは、ONTAP 9.20.1以降で正式にAFXストレージシステムに拡張され、9.19.1 P3でも利用可能です。これにより、データ量の多いワークロードをサポートする、はるかに大規模なデータスケールが可能になります。AFXの実装ではいくつかのアーキテクチャ上の変更が導入されていますが、ONTAP機能の主要な特性は変わりません。



 a| 
FSA - 正確なディレクトリアクセス時間
 a| 
File System AnalyticsのスキャンとSystem Manager File System Explorerのブラウジングでは、ディレクトリのアクセス時間（atime）メタデータが保持されます。これにより、アーカイブ、階層化、コンプライアンス、およびデータのライフサイクルワークフローの正確なatime値を維持できます。



 a| 
FlexCacheボリューム指標
 a| 
FlexCacheボリュームのメトリクスは、FlexCacheボリュームとそのオリジンボリューム間で交換されたデータとメタデータの量を報告します。既存のONTAP RESTボリューム統計およびメトリクスエンドポイントに2つの新しいプロパティが追加され、FlexCacheからオリジンへ、およびオリジンからFlexCacheへのデータ転送を可視化できるようになりました。カウンタは設定不要で自動的に収集され、キャパシティプランニング、パフォーマンス分析、ネットワークのトラブルシューティング、およびチャージバック分析に役立ちます。この機能を使用するには、FlexCacheノードとオリジンノードの両方でONTAP 9.20以降が必要です。詳細については、ONTAP自動化のドキュメントを参照してください。



 a| 
クラスター内リバランス
 a| 
ONTAPでは、ワークロードやクラスタ容量の変化に合わせて、最小限の管理作業でクラスタのパフォーマンスを最適に維持できるよう、2つの新しいバランス配置機能が導入されました。プロビジョニング時の配置制御により、REST APIを介して新しいボリュームを配置する際に、パフォーマンス要件とスペース要件のどちらを優先するかをお客様が指定できます。スペースパフォーマンス再調整（SPR）は、クラスタ全体で発生しつつあるパフォーマンスのホットスポットやアグリゲートのスペースの逼迫を継続的に監視するバックグラウンドプロセスです。設定されたモードに応じて、SPRはEMS通知を介して修正のためのボリューム移動を推奨するか、標準的で無停止のONTAPボリューム移動処理を使用して自動的に移動を実行します。詳細については、ONTAP自動化のドキュメントを参照してください。



 a| 
オブジェクトを含むONTAP S3バケットの削除のサポート
 a| 
管理者は、設定可能な保持期間ベースの復旧期間を使用する場合、オブジェクトを含むバケットの削除をスケジュールできます。これにより、保持期間が終了する前にバケットを復元することが可能になります。この機能により、有効期限切れのバックログが削減され、変更の激しいワークロードにおける容量の再利用が迅速化されます。



 a| 
S3 NASバケットのSVM移行をサポートします
 a| 
ONTAP 9.20.1は、FlexVolボリューム上でS3 NASバケットをホストするSVMのSVM移行をサポートしており、管理者はS3 NASの設定を事前に削除することなくSVMを移行できます。



 a| 
FlexGroupボリュームの再利用可能なスペースを計算する
 a| 
ONTAPは、FlexGroupボリューム上のスナップショットを削除する前に、再利用可能な領域を計算することをサポートしています。



 a| 
非同期削除のパフォーマンス向上
 a| 
ONTAPは、非同期削除のパフォーマンスを向上させ、NAS/SMBクライアントの領域解放を加速します。詳細については、NetAppの担当者にお問い合わせください。



 a| 
ハイパフォーマンスなFlexGroupボリュームの自動プロビジョニング
 a| 
ONTAPは、お客様がワークロードに合わせてバランスの取れた、またはハイパフォーマンスなデータ コンテナを選択できるストレージプロファイルによって、FlexGroupのプロビジョニングを簡素化します。これにより、管理者がパフォーマンス要件を満たすために構成要素となるボリュームを手動で構成およびサイズ設定する手間が軽減されます。



 a| 
NVFAILサポート（FlexCache）
 a| 
NVFAILが有効なオリジンとのFlexCache関係を作成できます。キャッシュボリュームに対しても、オリジンボリュームとは独立してNVFAILを有効にできます。NVFAILが発生したオリジンボリュームまたはキャッシュボリュームでは、ONTAPはデータの読み取りや変更をブロックしつつ、変更されたキャッシュデータの書き戻しは維持し、復旧後に通常のI/Oが再開されます。

== System Manager

[cols="30%,70%"]
|===
| 更新 | 説明 


 a| 
証明書およびユーザーパスワードの有効期限切れアラートのサポート

システムマネージャは、クラスタまたはストレージ仮想マシン（SVM）の証明書の有効期限が切れる30日前にダッシュボードの健全性アラートを表示し、有効期限までの残り日数を毎日更新します。

また、ユーザーアカウントに関連付けられた役割でパスワード有効期限切れアラートが設定されている場合、パスワードの有効期限が切れる14日前から、ログイン直後にSystem Managerのページ上部にバナーアラートが表示されます。アラートはユーザーがログインするたびに更新され、パスワードの有効期限が切れるまでの残り日数が表示されます。管理者ロールを追加または編集する際に、有効期限切れアラートを設定できます。
