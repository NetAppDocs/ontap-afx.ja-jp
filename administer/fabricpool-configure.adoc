= FabricPool を AFF ストレージシステム向けに設定する
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
大まかに言うと、AFFストレージシステムでFabricPoolを設定して有効化するには、2つの異なるレベルでのプロセスが含まれます。まず、クラスタレベルでデータ用のクラウド階層を定義する必要があります。その後、複数の階層化ポリシーのいずれかを使用して、特定のボリュームに対して階層化を有効化できます。



[[configure-fabricpool-at-the-ontap-cluster-level]]
== ONTAPクラスターレベルでFabricPoolを設定する

ONTAPクラスター全体で利用可能な単一のオブジェクトバケットを定義する必要があります。FabricPoolデータ階層化が有効なすべてのボリュームは、同じバケットを使用します。

.タスク概要
アグリゲートごとのアタッチを含む 2 段階のプロセスを採用する ONTAP とは異なり、AFX はオブジェクトストアを構成し、すべてのノードをバケットにアタッチするために、単一のクラスタスコープのプロセスを使用します。接続も確認され、オブジェクトストアとの関連付けは永続的です。

クラウド層の構成はSystem Managerを使用して説明しますが、他のオプションも利用可能です。たとえば、CLIで `cluster object-store config create`コマンドを使用できます。詳細については、link:../administer/fabricpool-additional.html["AFXストレージシステムでFabricPoolを使用する場合の追加の考慮事項"]を参照してください。

.開始する前に
* AFX FabricPoolの前提条件を確認してください。例えば、クラスターが9.19.1以降のレベルであり、以前のリリースからアップグレードされたものではないことを確認してください。詳細については、link:../administer/fabricpool-prepare.html["AFXストレージシステムにFabricPoolを実装するための準備"]を参照してください。
* オブジェクトストアバケットをプロビジョニングします。NetApp StorageGRID または ONTAP S3 のいずれかに、お客様のデータに十分な容量を備えたバケットを作成します。より安全な接続を実現するために、オブジェクトストアに CA 証明書をオプションでインストールできます。
* クラスター間LIFを作成し、オブジェクトストアへの接続を確認します。AFXクラスター内の各ノードにあるオブジェクトストアにアクセスするには、クラスター間LIFのペアを定義する必要があります。すべてのノードがオブジェクトストアのエンドポイントに到達できること、および名前解決が正常に機能していることを確認してください。


.手順
. System Manager で、左側のナビゲーションペインの *Cloud Tiers* メニュー項目を選択します。
+
クラウド層が設定されていない場合は、「追加」ボタンが表示された空の状態ページが表示されます。

. クラウド階層の作成を開始するには、「追加」を選択します。2つのオプションを含むダイアログが表示されます。
. プロバイダーとして StorageGRID または ONTAP S3 を選択します。適切な「クラウドティアの追加」フォームが開きます。
. 必要なオブジェクトストア情報を入力してください。以下の情報が含まれます：
+
.. オブジェクトストア名（構成識別子）
.. サーバー名（オブジェクトストアエンドポイントのFQDNまたはIPアドレス）
.. コンテナ名（バケット名）
.. アクセスキーとシークレットキー（オブジェクトストアの認証情報）
.. 証明書の検証設定（推奨：適切な認証局証明書で有効にする）


. クラウド層のトラフィックを伝送するクラスター間LIFを選択します。
+
適切なインターフェースが存在しない場合は、新しいインターフェースを作成するオプションが提供されます。

. *保存*を選択します。
+
System Manager は、クラスタレベルのオブジェクトストア構成を作成し、ネットワーク接続を確認した後、クラスタ内のすべてのノードに自動的に接続します。

. クラウドティアの詳細については、「クラウドティア」ページカードをご確認ください。


.終了後の操作
クラスターダッシュボードの容量カードにクラウド階層の使用状況が表示されていることを確認してください。割り当てられたバケットは、FabricPool で使用するものとして識別された後は、名前を変更できないことに注意してください。必要に応じて、個々のデータボリュームに対して階層化を有効にすることができます。



[[enable-tiering-with-volume-level-policies]]
== ボリュームレベルのポリシーを使用して階層化を有効にする

FabricPoolがクラスタレベルで構成されると、適切な階層化ポリシーを設定することで、個々のボリュームで階層化を有効にできます。一般的に、ポリシーは AFX でも ONTAP と同様に動作します。

* *ボリュームレベルの階層化。*階層化はボリューム単位で有効化されます。ボリュームごとに異なる階層化ポリシーを設定できます。ボリュームのデータは、ポリシーに基づいてクラウド層に移動する対象となります。
* *階層化ポリシー。*ボリュームに対して定義できる階層化ポリシーは4種類あります。次のものが含まれます：
+
** `snapshot-only`
** `auto`
** `all`
** `none`


* *デフォルトの階層化ポリシー*デフォルトのポリシーは `none`です。つまり、クラウド層に移動できるデータは存在しないということです。一方、新しくアタッチされたアグリゲートの ONTAP ボリュームは、AFF および FAS システムではデフォルトで `snapshot-only`になります。
* *ポリシーのトリガー* `none`以外のポリシーを設定すると、クラウド接続がトリガーされ、データ階層化が有効化されます。
* *冷却期間。*冷却期間とは、データが階層化の対象となるまでに、どのくらいの期間非アクティブ状態を維持しなければならないかを決定する期間です。CLIを使用する場合、これは通常、 `-tiering-minimum-cooling-days`パラメータを使用して設定されます。デフォルトの冷却期間は、自動ポリシーの場合は31日間、スナップショットのみの場合は実質的に約2日間です。各ボリュームのワークロードに合わせて、これを調整できます。
* *温度追跡。*AFX では、温度追跡はアグリゲートレベルではなく、ボリュームごとに実行されます。


FabricPool 階層化ポリシーの詳細については、 https://docs.netapp.com/us-en/ontap/fabricpool/tiering-policies-concept.html["ONTAP FabricPoolポリシーでデータを効率的に階層化"^]を参照してください。



[[activate-volume-level-tiering-and-next-steps]]
=== ボリュームレベルの階層化を有効にして次のステップに進む

ボリュームで階層化を有効にするには、System Manager で「*Volumes*」ページに移動し、「*Edit*」を選択してから「*Cloud Tier Settings*」を選択して、必要に応じて各ボリュームの階層化ポリシーと冷却期間を設定します。デフォルトのポリシーは「なし」なので、階層化はボリュームごとに明示的に有効にする必要があります。CLI で既存のボリュームコマンドを使用できます。

階層化が開始されたら、階層化の状況と容量利用率を監視する必要があります。また、ボリューム階層化の状態を確認し、パフォーマンス階層と容量階層の容量使用状況を監視してください。AFX では Inactive Data Reporting（IDR/AutoIDR）が無効になっているため、階層化可能なデータ／コールドデータの測定方法は AFF または FAS システムとは異なる方法で計画してください。
